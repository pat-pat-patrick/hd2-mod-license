# HD2 Mod License 协议（草案 1，2026-11-02）

MOD 作者用它把 MOD 限定给自己的会员使用。会员在管理器中登录作者的发证服务器，取得签名的授权文件；MOD 在游戏加载时用作者的公钥离线核对。游戏运行时不联网。

## 角色

| 角色 | 做什么 | 实现 |
|---|---|---|
| 发证方 | 判断会员身份，签发、续期授权 | 作者自己的服务器；`worker/` 是基于 Patreon 的 Cloudflare Worker 模板 |
| 管理器 | 读取 MOD 的声明，登录、取回、续期、写入授权 | HD2 Mod Quick Deploy 的授权插件 |
| MOD | 加载时核对授权 | `lua/license_check.lua` |

每个发证方以自己的主机名区分，例如 `license.example.com`，下文称为「发证方名称」。

## 1. MOD 的声明

需要授权的 MOD 在包的根目录放 `hd2_license.json`：

```json
{
  "protocol": 1,
  "issuer": "license.example.com",
  "name": "作者或频道名称",
  "key": "<RSA-2048 公钥模数 n，十六进制>"
}
```

- `issuer`：发证方名称，只含小写字母、数字、`.` 和 `-`。管理器访问 `https://<issuer>/`。
- `name`：管理器显示给玩家的名称。
- `key`：与 MOD 内嵌的公钥相同。`worker/lua_key.mjs` 同时输出这个文件和 Lua 用的公钥。

## 2. 游戏账号标识

授权绑定的是游戏账号，不是电脑。

- **游戏内：** `Network.peer_id()`，16 位十六进制。
- **管理器：** `%APPDATA%\Arrowhead\Helldivers2\saves\` 中 `<标识>_user_settings.config` 的文件名前缀。一台电脑上可能有多个。

两者是同一个值（已证实：同一账号自 2026-09-23 起，跨越 10-20 的游戏补丁，值始终不变）。

## 3. 发证方接口

所有响应为 JSON，`/login` 与回调页面除外。

| 请求 | 用途 | 成功 | 失败 |
|---|---|---|---|
| `GET /login?n=<随机数>&acct=<标识>[,<标识>]` | 管理器在浏览器中打开；跳转到会员平台登录 | 302 | 400 页面 |
| `POST /claim {"n": "<随机数>"}` | 管理器轮询登录结果，只能取一次 | `{"license", "renew"}` | 404 `{"pending": true}`；403 `{"error"}` |
| `POST /renew {"renew": "<续期凭据>"}` | 到期前续期 | `{"license"}` | 403 `{"error"}` |

- `n`：管理器生成的 32 位十六进制随机数，10 分钟内有效。
- `renew`：64 位十六进制，管理器保存在自己的数据中，不放进游戏目录。重新登录后旧凭据失效。
- `error` 的取值：

| 值 | 含义 | 管理器的处理 |
|---|---|---|
| `not_member` | 不是有效会员，或档位不够 | 提示玩家，停止续期 |
| `account_limit` | 已绑定的游戏账号达到上限 | 提示联系作者 |
| `denied` | 玩家在会员平台拒绝了授权 | 提示可重新登录 |
| `sign_in_again` | 续期凭据仍有效，但需要重新登录 | 提示重新登录 |
| `unknown` | 续期凭据无效 | 提示重新登录 |

## 4. 授权文件

管理器写入 `%APPDATA%\Arrowhead\Helldivers2\licenses\<issuer>.txt`，内容原样保存发证方返回的文本：

```
HD2 MOD LICENSE 1
issuer=<发证方名称>
accounts=<标识>[,<标识>]
issued=<unix 时间>
expires=<unix 时间>
holder=<发证方自定的持有人标识>
sig=<签名，十六进制>
```

- **签名：** RSASSA-PKCS1-v1_5，SHA-256，RSA-2048，覆盖 `sig=` 行之前的全部字节。
- **换行：** 签名时为 LF。检查时去掉 CR，所以被编辑器改成 CRLF 不影响。
- **未知字段：** 检查方忽略，但它们在签名范围内。

## 5. 管理器的行为

1. 添加或更新 MOD 时读取 `hd2_license.json`，在 MOD 列表中标出需要授权、已授权或已过期。
2. 第一次向某个发证方登录前，告诉玩家发证方名称，以及游戏账号标识会发送给它。
3. 记住每个发证方第一次见到的公钥。之后若有 MOD 对同一发证方声明了不同的公钥，提醒玩家，不自动采用。
4. 剩余有效期不足一半时，在后台续期。
5. 先写入临时文件再改名，避免游戏读到写了一半的文件。

## 6. MOD 的行为

1. 嵌入 `license_check.lua` 和自己的公钥。
2. 加载时调用一次 `check(KEY)`，不在每帧调用。一次约 10 ms（PUC Lua 5.1，hd2fake 实测）。
3. 返回 `no_account` 时，游戏还没有给出账号标识，稍后再试。
4. 其他失败：原因见下表。怎么处理由作者决定，建议写入日志并不启动功能。

| 原因 | 含义 |
|---|---|
| `missing` | 没有授权文件 |
| `malformed` | 文件格式不对 |
| `issuer` | 授权来自另一个发证方 |
| `signature` | 签名不对：被改过，或不是这个公钥签的 |
| `expired` | 已过期 |
| `account` | 授权中没有当前游戏账号 |

## 限制

- 签名保证授权无法伪造。但 MOD 的 Lua 可以被修改，修改者可以删除检查。本协议阻止的是把文件直接复制给他人。
- 检查用的是玩家电脑的时间，调整系统时间可以延长有效期。
- 发证方能看到玩家的游戏账号标识，以及玩家在会员平台的身份。

## 版本

协议版本号写在授权文件首行（`HD2 MOD LICENSE 1`）和 `hd2_license.json` 的 `protocol` 中。不兼容的修改会使用新的版本号。
